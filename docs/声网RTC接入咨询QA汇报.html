AGORA RTC · QA SUMMARY

声网 RTC 接入咨询 QA 汇报

围绕媒体层切换、全球互通、直播与通话并行、媒体加密、Token、计费和 Web/H5 兼容性，整理统一汇报口径。

01架构与业务支持

Q1

把 App 上的音视频 RTC 服务切换为声网媒体层，需要申请什么服务、做哪些操作？

需要先明确业务中所指的“媒体层”具体含义与范围（是仅替换传输层、编解码，还是完整的音视频通信组件）。

Q2

用户以海外为主，但也包含大陆用户，是否只需申请海外业务？大陆与海外用户互通会有问题吗？

声网 RTC 具备全球节点网络，用户会就近连接接入点，支持跨地域通话互通。

Q3

声网的直播和 RTC 是同一个 SDK 还是分开的？在同一个 App 中同时支持二者是否有冲突？

极速直播与互动直播使用的是同一个 SDK，底层均基于 RTC 技术实现，不存在冲突。

Q4

用户在看直播时收到 RTC 通话请求，直播和通话是否存在冲突？应该如何处理方案？

底层均属于 RTC 服务；当前建议先验证实际体验，不必一开始就将“多频道”或“自采集”设为刚需方案：

  • 单频道方案（优先推荐评估）：若业务接受“接听时暂停/离开直播频道，通话挂断后再返回直播”，建议优先采用此方案。
  • 多频道并行方案：若强诉求通话期间仍需在后台/画中画保持直播收看，再深入讨论并行双频道方案。
Q5

直播和音视频业务区分不同账号、不同 App ID 是否支持？有什么潜在影响？

不同 App ID 业务不能互通。我们本来就要做业务风险隔离，不需要互通。

02安全性与加密机制

Q6

声网的默认加密方式（如 AES-GCM2）是否安全？推荐 AES-128 还是 AES-256？是否影响通话质量？能否自定义加密？

建议选用 AES-128 或 AES-256。在移动端开启后不影响通话质量，但官方不支持自定义加密算法。

Q7

国内通话是否也支持加密？

支持，国内通话与海外场景一致，均默认支持 AES-128 / AES-256 加密方式。

Q8

使用声网官方 SDK 进行 AES 媒体加密传输，后台是否会悄悄上报或泄露密钥（Key / Secret）？

  • Native 端（iOS / Android）：官方明确声明，媒体端到端加密的密钥不会上传至声网服务器。
建议：各个端走查一下声网源码更为稳妥。

03Token 与计费规则

Q9

每次通话申请的 Token 是否有限流机制？

Token 本身没有限流机制。

Q10

RTC 的计费规则是按 Token 申请时长、还是按网络流量（GB）？

既不是按 Token 的有效期，也不是单纯按流量（GB）计费；RTC 基础计费是根据实际通话消耗的人分钟数（User-Minutes）、音视频类型及分辨率档位进行综合计费。

04平台与浏览器兼容性

Q11

声网 H5/Web SDK 支持哪些浏览器？是否支持 Telegram 内嵌浏览器？兼容性如何？

  • 浏览器官方兼容性列表参考：https://doc.shengwang.cn/doc/rtc/javascript/overview/browser-compatibility
  • Telegram 内嵌浏览器：官方未进行专项测试，目前无法确保兼容性，需实际联调验证。
