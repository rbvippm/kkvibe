# 移动端 PRD 标注规范

> 适用于 H5 / 代理端移动原型。与 PC 后台 `WfSpecAnnot` **分离**，不得混用数据结构。

## 1. 与 PC 标注的差异

| 维度 | PC（WfSpecAnnot） | 移动端（Mh5SpecAnnot） |
|------|---------------------|-------------------------|
| 组件 | `src/components/wireframe/WfSpecAnnot.vue` | `src/components/mobile/Mh5SpecAnnot.vue` |
| 数据类型 | `{ title, items: string[] }` 简版条目 | `MobilePrdSpec` 含 **六大结构** |
| 触发 | 悬停 / 聚焦 | **点击** 切换；遮罩关闭 |
| 浮层标签 | 「需求说明 #N」 | 「**移动端 PRD · #N**」 |
| 编号 | 每页 `{MODULE}_SPEC_ANNOT_NO` 从 1 起 | 同左，写在 `{module}Spec.ts` |
| 文档页 | 需配 `docRouteName` 文档子页 | 原型阶段仅浮层，不强制文档路由 |

## 2. PRD 六大结构（必填）

每条移动端标注的 `sections` 必须按顺序包含以下 6 节，每节至少 1 条 `lines`：

1. **功能逻辑** — 模块做什么、业务目标、主链路  
2. **交互行为** — 用户动作 → 系统反馈 / 状态变化  
3. **视觉表现** — 布局、颜色、组件状态、动效（**仅业务 UI，见 §4.1**）  
4. **数据规则** — 格式、枚举、限制；**用界面中文名，禁止代码字段名**（见 §4.3）  
5. **异常与边界** — 错误文案、空状态、超时、权限  
6. **关联与跳转** — 入口、出口、路由名、页面勾连  

类型与工具见 `src/constants/mobilePrdSpec.ts`：

- `MobilePrdSpec` / `MobilePrdSpecSection`  
- `MOBILE_PRD_SECTION_META` — 各节中文名与撰写提示  
- `buildMobilePrdSections()` — 按固定顺序组装；**视觉表现** 节自动追加 `MOBILE_PRD_VISUAL_DESIGN_DRAFT_NOTE`  
- `MOBILE_PRD_VISUAL_DESIGN_DRAFT_NOTE` — 「颜色、字号以实际设计稿为准。」

## 3. 落地步骤

1. 在 `src/constants/{module}Spec.ts` 定义 `AGENT_*_SPEC_ANNOT_NO` 与 `MobilePrdSpec` 常量。  
2. 使用 `buildMobilePrdSections({ logic: [...], interaction: [...], ... })` 填充六大块。  
3. 在页面 **二级顶栏右侧 slot** 挂载：  
   ```vue
   <Mh5SubPageHeader title="页面标题">
     <template #right>
       <Mh5SpecAnnot :spec="XXX_SPEC" placement="bottom" />
     </template>
   </Mh5SubPageHeader>
   ```  
4. 样式已在 `mobile-app-shell.css` 的 `.mh5-spec-annot__*` 中统一维护，业务页勿重复写。  
5. 浮层须可滚动：内容区 `.mh5-spec-annot__panel-body` + `max-height` 自适应视口。

## 4. 撰写要求

### 4.1 视觉表现：禁止描述标注入口

**视觉表现** 只写本页 **业务功能** 的 UI，禁止出现以下内容：

- 「注N」「需求说明」「PRD 浮层」「标注触发」等标注组件自身的位置、样式、交互  
- 顶栏右侧注标、橙色「注」字触发器等 **元信息**  

标注入口的统一样式由 `Mh5SpecAnnot` + `mobile-app-shell.css` 维护，不在各功能 PRD 中重复描述。顶栏标题若属业务文案（如「邀请现有会员为下级」）可写；与「注N 并列出现」的写法不可写。

### 4.2 视觉表现：颜色与字号以设计稿为准

**视觉表现** 中涉及 **颜色、字号** 等视觉细节时，须在节末追加统一说明（常量 `MOBILE_PRD_VISUAL_DESIGN_DRAFT_NOTE`）：

> 颜色、字号以实际设计稿为准。

- 使用 `buildMobilePrdSections()` 时 **自动追加**，业务 `*Spec.ts` 无需手写重复条目。  
- 原型阶段 PRD 中的色值、px 仅作实现参考；交付以 UI 设计稿为最终依据。

### 4.3 数据规则：使用界面文案

**数据规则** 面向产品评审，须用 **页面上的中文名称** 描述，禁止出现：

- 代码字段名（如 `nickname`、`memberAccount`、`status`）  
- 英文枚举值（如 `pending`、`accepted`）  
- 实现细节缩写（如 `trim`、`Mock`、`query`）  

应写：**昵称**、**金刚号**、**待确认**、**发送时间** 等与 UI 一致的叫法；状态枚举写中文全名。实现层字段映射由研发对照 `constants/*` 自行对齐。

### 4.4 通用要求

- **尽量详细**：面向研发与测试可直接评审，避免「见 PRD」式空话。  
- **可验证**：交互、异常请写清具体按钮文案与 Toast/弹窗内容。  
- **Mock 一致**：数据规则须与 `constants/*` 中 Mock 字段、枚举一致。  
- **路由写全**：关联与跳转写 `name` 或用户可见入口路径。  
- **一注一功能**：同一页面多标注时编号递增，不跨页复用编号。

## 6. 禁止事项

- 禁止在移动端使用 `WfSpecAnnot` 或 PC 的 `items[]` 简版结构。  
- 禁止省略六大结构中的任一节。  
- 禁止把「注」放在可点击的主按钮 **内部**（应放顶栏右侧或标题旁，点击不触发主流程）。  
- 禁止在 **视觉表现**（及其他五节）中描述 **标注入口 / PRD 浮层** 本身（见 §4.1）。
