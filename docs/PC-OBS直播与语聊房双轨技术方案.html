AGORA RTC · RTM · MEDIA GATEWAY · OBS

PC + OBS 视频直播与语聊房双轨技术方案

在保留现有 App / H5 看播链路的前提下，将“专业内容生产”和“超低延时互动”拆成两条最适合各自场景的技术轨道。

视频直播：OBS + 云端媒体网关 语聊房：PC Web + Agora Web SDK 本期范围：不做第三方分发 既有观众端：尽量零改动
双轨落地专业生产与互动能力分离
200–400ms纯 RTC 语聊目标体验值
RTMP / SRTOBS 标准推流入口
复用现有端App / H5 继续走 RTC 看播
01

结论摘要

先明确场景，再选择传输链路，不追求用一个方案覆盖全部需求。

✓
推荐：“视频走 OBS 网关，语聊走 WebRTC”

视频直播优先保障画质和 OBS 编排；语聊房优先保障低延时、设备控制和主持交互。

1PC 后台生成推流任务与 OBS 推流凭证。
2OBS 通过媒体网关注入现有 RTC 直播频道。
3PC Web 完成语聊房主持、连麦和音频设备闭环。
本期范围：只增加 PC 视频开播和 PC 语聊主持能力，不建设第三方标准拉流、CDN 外推和外部页面嵌入。
02

PC 开播候选方案对比

两个方案都成立，但适用场景不同，不建议互相替代。

评估维度 方案一：声网云端媒体网关 方案二：PC Web + Web SDK
核心路径 OBS 原生推流（RTMP/SRT）→ 云端网关 → 注入指定 RTC 频道 浏览器采集 OBS 虚拟摄像头/声卡 → agora-rtc-sdk-ng → RTC 频道
研发工作量 极低：后端创建网关任务、生成推流凭证，后台展示配置 较低：建设 Web 开播台，复用现有 Token 与频道机制
目标延时 约 800ms–2s：受推流协议、缓存和云端处理影响 约 200–400ms：纯 WebRTC，适合高频对话
OBS 专业编排 完整发挥：多场景、贴片、字幕、采集卡、导播 依赖虚拟摄像头和虚拟声卡，配置成本更高
实时连麦 弱：OBS 是单向生产端，远端画面回采与混流复杂 强：原生订阅远端轨道，可同屏审核、控麦和互动
未来分发扩展 便利：OBS 流已进入 RTC，后续可在云端增加旁路推流，不需要主播重新配置多路上行 同样可复用 RTC 频道增加云端分发；该能力明确不纳入本期
主要成本 现有 RTC + 新增媒体网关/转码费用 常规 RTC/RTM；前端兼容与设备支持成本较高
推荐场景 视频直播、赛事、活动、买量投流 语聊房、主持连麦、多人互动、PK

延时数据为方案评估目标值，不是 SLA；最终结果取决于主播网络、地区、协议、转码档位和观众接入方式。

03

双轨总体架构

复用频道、Token、房间状态和审核体系，媒体生产端按场景拆分。

轨道 A · 视频直播
PC 运营后台→ 创建直播任务→ OBS RTMP / SRT→ Media Gateway→ Agora RTC 频道
轨道 B · 互动语聊
PC Web 主持台→ 麦克风 / 声卡→ Agora Web SDK→ Agora RTC 语聊房 +
RTM 控制信令运营审核后台
共享底座

统一业务身份

频道 ID、主播 UID、Token、直播场次和审核权限由同一服务端生成。

保持兼容

观众端尽量不改

App/H5 继续订阅现有 RTC 频道，只需兼容新增的 PC 开播来源。

职责隔离

媒体与控制分层

RTC 传输音视频；RTM/业务 WebSocket 传递举手、禁言、席位和任务状态。

本期涉及的声网服务明细

区分既有能力复用、必须新增接入和本期明确不需要的服务。

声网服务 / 能力 本期状态 具体用途 接入位置 商务与技术核验
Agora RTC 复用 · 必须 承载视频直播频道和语聊房音频频道；App/H5 继续订阅，PC Web 主持人发布和订阅音频。 复用现有 App ID、Channel、UID、主播/观众角色和看播链路。 确认 PC Web 新增分钟数及现有套餐并发。
Agora Media Gateway 新增 · 必须 接收 OBS 的 RTMP/SRT 流，将专业制作流注入指定 RTC 频道。 PC 后台触发；服务端通过 REST API 创建、查询和停止网关任务。 确认账号开通、区域、输入协议、分辨率、并发配额和增值计费。
Agora Web SDK NG 新增 · 必须 PC 语聊主持人入房、发布麦克风、订阅连麦用户、切换设备、控制音量和音效。 运营后台集成 agora-rtc-sdk-ng，推荐限定 Chrome / Edge。 确认目标版本的变声、美音和输出设备 API 支持矩阵。
Agora RTM / Signaling 复用 · 必须 传递举手、上麦审核、静音、踢下麦、麦位状态和主持操作信令。 复用现有语聊房业务协议，在 PC Web 补齐 RTM 客户端接入。 确认消息量、登录并发、Token 续期和断线恢复策略。
AccessToken2 / Token 服务 复用 · 必须 为 OBS 注入任务、PC 主持人和现有观众签发短时 RTC/RTM 权限。 继续由现有服务端持有 App Certificate 并签发 Token。 无需新建账号体系，仅增加 PC 来源和对应权限校验。
Media Gateway REST API / 回调 新增 · 必须 控制网关任务生命周期，获得连接、首帧、断流、失败和停止状态。 作为现有开播服务的增量适配层，不新增独立直播业务模型。 确认鉴权方式、回调签名、幂等规则、限流和错误码。
旁路推流 / Media Push / CDN 本期不使用 后续需要买量投流或外部嵌入时，再将 RTC 频道流推送到 CDN 或第三方平台。 本期不开发、不配置、不产生对应 CDN 分发链路。 仅保留架构扩展位，不纳入本期报价和排期。
云端录制 本期不新增 本次 PC 开播改造不依赖云端录制；如现有业务已使用则保持原逻辑。 不因 PC 开播重复建设。 不纳入本次增量范围。
继续复用

RTC、RTM、Token

频道、用户身份、房间状态和 App/H5 看播链路不重做，只补齐 PC 端角色。

本期新增

Media Gateway + Web SDK

新增成本集中在 OBS 入流网关和 PC Web 主持端开发，不扩建整套直播后端。

本期排除

旁路推流、CDN、云录制

第三方标准拉流和外部嵌入留到后续独立版本评审。

产品名称提示：声网控制台中的“Media Gateway、Signaling、Media Push”等名称、能力入口和计费口径可能随区域及版本调整，正式采购前需由声网技术支持和商务按当前账号确认。

视频直播：OBS + 云端媒体网关

重画质、重导播，本期只注入现有 RTC 频道，不建设第三方分发。

主播闭环
01

后台创建场次

复用现有直播场次，选择频道、主播、清晰度和 PC-OBS 开播来源。

02

服务端创建网关任务

调用声网 REST API，绑定 RTC Channel / UID，生成推流地址和 Stream Key。

03

OBS 配置与预检

完成编码、码率、关键帧、音频采样率和网络上行测试。

04

首帧确认后开播

服务端收到网关回调并确认 RTC 首帧，场次才切换为“直播中”。

05

停止与资源回收

停止 OBS、关闭网关任务，并复用现有直播结束与房间回收逻辑。

OBS 推荐模板
配置建议值
输出编码H.264 + AAC，优先硬件编码
分辨率720p / 1080p，禁止无意义上采样
帧率25/30fps；赛事类视需求评估 50/60fps
关键帧建议 2 秒，需与 Media Gateway 输入要求一致
码率按声网网关注入 RTC 的推荐档位配置
音频48kHz、AAC，避免多重增益和重复降噪
SRT 更抗弱网、延时通常更低，但需确认当前声网区域、网关版本和主播 OBS 版本是否完整支持；首期可优先 RTMP，再灰度 SRT。

后续扩展第三方分发的便利优势

无需改 OBS

主播只保持一路上行

OBS 流已经通过网关进入声网云端，后续增加第三方分发时，可由云端分流，无需主播电脑多路推流。

无需改观众端

现有 RTC 主链路保持稳定

App/H5 继续看 RTC；未来的 CDN 或外部平台只是云端新增出口，不影响现有看播和 PC 开播流程。

统一控制

后台按场次开关

后续可独立增加分发任务、权限、计费和状态监控，不需要重做直播房间、主播身份和 OBS 配置。

本期不实施：不开发旁路推流、CDN 输出、标准拉流地址、外部播放器或广告平台适配；这里只说明双轨架构为后续扩展保留的便利性。

07

安全、稳定性与监控

推流码、Token、设备权限和供应商回调都属于敏感控制面。

安全
  • 声网 App Certificate 仅保存在服务端。
  • RTC/RTM Token 短时有效并支持续期。
  • 推流码按场次生成，停播立即失效。
  • 复制和查看推流码写入后台审计日志。
  • 回调校验签名、时间戳并防重放。
监控
  • OBS 是否连接、首帧耗时和断流次数。
  • RTC 入会成功率、网络质量和音频卡顿。
  • 网关创建成功率、RTC 首帧和状态回调延迟。
  • 麦克风静音、爆音、无声和设备切换失败。
  • 网关任务时长、并发占用和增量费用。
容灾
  • OBS 短断流保留任务并限次自动恢复。
  • 网关任务失败允许重新创建，不复用脏状态。
  • PC-OBS 开播异常不影响既有 App 开播能力。
  • 语聊设备拔插自动回退系统默认设备。
  • 运营后台刷新后恢复当前场次上下文。
费用防护：媒体网关任务必须设置最大运行时长、结束兜底定时器和异常费用告警，避免主播关闭后台但云端任务持续计费。
